4 · Finding the centre

Block 4: the scan returns a list of blobs. This block decides which of them are the two boundaries and where the track centre is. Source: labs/lanedet/centre.py (51 lines) and the memory in detector.py.

Expected width decidescentre.py · estimate_centre()

From the camera model (page 3) we know how wide the track should look on this row: half_px = 42.8 px on the near band. Every blob pair is checked against that width, so a cone between the lines cannot fool it.

Pair rule: error = |gap − 2·half_px| / (2·half_px) < 0.35. Confidence = 1 − error / 0.35, so a perfect-width pair scores 1.

One line: which side is it?single-line hypotheses

A lone blob could be the left line (centre = u + half_px) or the right line (centre = u − half_px). The detector picks the hypothesis closest to the prior, where it expects the centre to be.

A single line is ambiguous. The prior resolves it, so the prior must be good.

Memory: last frame is the best priordetector.py · prev_x

The car moves a few millimetres per frame, so last frame's centre is an excellent guess. The detector stores it as prev_x in metres (one value serves both bands) and converts it to pixels on each row.

Without memory, e_lat flips sign past the boundary. With memory it saturates at ±1 on the correct side, which is the signal a controller needs to recover.
