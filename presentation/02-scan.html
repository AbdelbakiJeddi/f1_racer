Block 2: squash a thin band of mask rows into one row of numbers, then find the bumps. Those bumps are the lines. Source: labs/lanedet/scan.py, 33 lines.

Band → profilescan.py · band_profile()

We only need to know where across the image the lines are, at two chosen distances ahead. So take the near band (rows 68–74) and average each column down those 7 rows.

profile[u] = mean(mask[r0:r1, u]): 128×128 values become 128. The band's vertical position fixes how far ahead we look.

Why a band, not one rownoise σ = 45

A single row is fragile. One noisy speck becomes an extra "line", and one worn patch hides a real one. Averaging 7 rows dilutes both.

Trade-off: a taller band is more robust, but it smears slanted lines wider. 6–8 rows is the sweet spot used by both detectors.

Profile → linesscan.py · find_lines()

Walk left to right. Every unbroken run above level is a candidate line. Three numbers describe it:

massΣ profile over the run ≈ line width in pixels. Runs with mass < min_mass (1.0) are specks, so they are dropped.
u (centroid)mass-weighted mean column, Σ p·(c + 0.5) / Σ p. Column c spans [c, c+1).
clippedthe run touches the image border, so part of the line may be out of view.
The centroid is sub-pixel thanks to the soft mask (page 1). Partly covered edge pixels pull the balance point by fractions of a column.
