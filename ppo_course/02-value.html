2 · Value, Bellman and TD

How good is it to be here? Learning to predict the return without waiting for it.

Waiting for the end is too slowthe problem

The return Gt is only known when the episode ends, up to 1200 steps later. It is also noisy: the same situation can end well or badly by chance.

We want to answer, right now: "how good is it to be here?" That answer is the value.

same state, three runs of the same policy: G = 24.1 (drives the full 40 s) G = 18.7 (small wobble later) G = 9.3 (touches the line after 1.6 s) value = the average over all such runs

Value of a state, value of an actiondefinitions

Vπ(s) = E[ Gt | st = s ] state value Qπ(s,a) = E[ Gt | st = s, at = a ] action value

V: the return you expect from state s if you keep following policy π.

Q: the same, but forcing action a first, then following π.

Both depend on π: the same position is worth a lot to a good driver and little to a bad one. When the policy improves, the values change too. That is why the critic is retrained at every iteration.

The gap between Q and V is the core of the policy gradient (page 5): A(s,a) = Q(s,a) − V(s), how much better action a is than the policy's usual choice.

The Bellman equationderived from the return

Start from the recursive return of page 1:

Gt = rt + γ·Gt+1

Take the expectation of both sides, given st = s:

V(s) = E[ rt + γ·Gt+1 | s ] = E[ rt + γ·V(st+1) | s ]

The second line uses: the expected return from st+1 is V(st+1). This is the Bellman equation:

Bellman. The value here = the reward now + γ × the value of where you land.

It links each state's value to its neighbours'. It does not need the end of the episode: one step of experience is enough to check (and correct) a value estimate.

At a terminal state (off_track) there is no next state: V(s′) = 0. At a time-out the next state exists, so V(s′) stays. This is the γ·V(s) that rsl_rl adds on time-outs (page 0).

Break it: watch values spreadinteractive

A toy version of your track: 11 lateral cells, 8 cm apart. The outer cells are terminal (a wheel on the line). The policy is bad on purpose: each step it drifts one cell left (25 %), stays (50 %) or drifts right (25 %). Reward per step = the centering bell, 1 at the centre.

Two ways to compute V:

  • Bellman sweep: apply the equation to every cell at once, using the known drift probabilities.
  • TD learning: no probabilities given. Drive sampled episodes and correct V cell by cell from what happens (next section).

Exact values for γ = 0.99 (verified): centre 29.83, next to the line 9.64. With γ = 0.9 the centre is only 8.28: the far future barely counts.

To remember. Information travels one step per update: the line's danger reaches the centre only after many sweeps. In a real network, this is why the critic needs many iterations before its values are useful.

Monte Carlo vs Temporal Differencetwo ways to learn V

We do not know the drift probabilities of the real car. We only have experience. Two ways to use it:

Monte Carlo (MC)Temporal Difference (TD)
target for V(s)the real return Gtrt + γ·V(st+1)
wait forthe end of the episodeone step
biasnone (real outcome)yes: uses the current, imperfect V
noise (variance)high: sums many random rewardslow: one random reward
updateV ← V + α(G − V)V ← V + α·δ
δt = rt + γ·V(st+1) − V(st) the TD error

δ is the surprise of one step: positive if the step went better than V predicted.

Using a guess (V) to build the target for another guess is called bootstrapping. It is what lets TD learn while driving, before the episode ends.

The α slider above shows the trade-off on step size: α = 0.02 converges slowly but accurately (centre 29.2 after 3000 episodes), α = 0.5 jumps around the truth (36.6 at the same point).

Why not just pick one? MC is unbiased but noisy; TD is steady but biased while V is still wrong. GAE (page 6) blends them with one parameter, λ = 0.95 in your config. δ defined here is the building block of GAE.

The critic in your projectV as a neural network

With continuous positions, speeds and angles, V cannot be a table. It is a network Vφ(s) with parameters φ:

critic: 8 inputs → 128 → 64 → 32 → 1 output (ELU activations, 11 521 weights)

It is trained like a regression: after each data collection, compute a target return for every sample, then minimise

value loss = ( Vφ(s) − target )²

That is Loss/value in TensorBoard. A value loss that keeps growing means the critic cannot keep up with the changing policy, or the rewards are badly scaled.

Why value_loss_coef = 1.0? The total loss adds the actor and critic terms (page 8). The coefficient balances them. With separate networks for actor and critic, as in your config, the gradients do not mix much, so 1.0 is a safe default.
Why the critic gets privileged inputs? Better inputs give better values, and better values give less noisy learning signals for the actor. The exact lateral error is far more informative than the camera estimate, and it costs nothing because the critic never runs on the real car.

Deep dive: why PPO learns V and not Q

Q(s,a) needs the action as an input and, to pick the best action, a maximisation over all actions. With continuous actions (steer, throttle) that maximisation is itself an optimisation problem. Methods like DDPG and SAC do learn Q, with an extra actor trained to maximise it.

PPO avoids this: it learns V(s) only, and estimates the advantage A = Q − V from real rewards plus V (page 6). The actor's job is then simply: make actions with positive advantage more likely.

The Bellman optimality equation, V*(s) = maxa E[r + γV*(s′)], defines the value of the best policy. Q-learning methods iterate it. PPO instead evaluates its current policy (Bellman expectation equation) and improves the policy by gradient steps.
